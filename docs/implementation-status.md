# Radio implementation and evidence — November 10, 2026

This repository implements neutral radio identity/catalog/rights/editorial/program contracts, ciphertext station persistence and playback facades, authenticated contribution/output boundaries, provisional progress, durable outro vesting and creator wallets, actual atomic point redemption, unbounded reward pricing, separate Groove catalogs, shared transition opportunities, rarity/completion/grant/delivery boundaries, complete-work commerce and scoped verified reporting. Versioned Groove catalog/stock/station policy publication and authorized reveal checkpoints are atomic and durable.

**November 17, 2026 — PostgreSQL store durability.** `@neophilism/distributed-radio-engine/postgres-durability` lets any host keep the SQLite stores (points, vesting, listener history, recording channels, station operations) durable in PostgreSQL without a persistent disk: SQLite stays the default and the only query engine; snapshots are restored digest-checked before stores open, writes are fenced by an ownership epoch, and a failed write is reported, never acknowledged. Five new tests run against a real PostgreSQL 16 (local and a CI service container): empty-directory restart restore of a real point ledger and vesting receipt, superseded-instance fencing, tampered snapshot, failed write/retry and configuration validation. No deployed host uses it yet; the Render preview remains status-only.

The full suite has 294 passing tests against the actual DAE build (November 17, 2026; none skipped, PostgreSQL suite included), including real SQLite restart/process races, actual DAE checkout/entitlements, official Stripe SDK raw-webhook signatures and music/documentary ciphertext chunk authentication. Tests use explicit fixture identity/rights, issuer, transport and provider callbacks where no real service is configured. They never establish actual speaker output, actual key enrollment, a real Stripe account or a deployed pilot.
